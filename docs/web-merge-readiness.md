## 自动化验收

`web-merge-checks.yml` 只有 `contents: read` 权限，在 PR、main、feat/web-deployment 和手动运行时执行：冻结锁文件安装、全量 Vitest、Web 构建、lint、四语言格式及键检查、接口清单一致性、Core/Web Rust 测试、Windows/macOS/Linux 桌面编译，以及 Docker/Chromium 验收。它不发布镜像，亦不需要仓库部署秘密。

执行真实部署验收：

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install --with-deps chromium
pnpm test:web:e2e
```

脚本为 `/` 和 `/nyaterm/` 分别构建生产 Docker 镜像，运行独立 OpenSSH/SFTP 容器及临时数据卷，生成临时凭据。用 Chromium 执行登录、指纹确认、终端输入输出、刷新附着、文本编辑保存、上传冲突/改名、二进制及普通下载、设置和编辑器子窗口、注销。失败保留 `artifacts/web-e2e/` 的 trace、截图和容器日志，finally 只删除脚本自己创建的容器、数据卷、网络、镜像标签及秘密目录。

本机 Rust 统一使用 `D:/nyaterm-build/web-merge`，没有清理用户的数据或构建目录。检查记录：

## 接口覆盖与历史基线

`pnpm web:audit` 使用 TypeScript AST 扫描生产 invoke 调用及条件分支字面量，结合浏览器适配器和 Rust 显式 allowlist，生成 `docs/web-api-inventory.json`；`pnpm web:audit:check` 检查清单是否与源码一致。动态表达式仍保留供人工检查。

清单中的 desktop-or-unmatched 包括已被能力隔离的桌面命令，不能当作 Web 缺陷数；server-allowlist 包括兼容占位接口，也不能当作端到端通过数。旧兼容审计中的 276/462/184 属于历史快照，其命令表和行号不再代表当前覆盖。当前功能范围见部署文档的能力矩阵。
